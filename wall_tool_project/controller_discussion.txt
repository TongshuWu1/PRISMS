Active Controller
-----------------
The selected controller is:
  control_law = "sensor_cascade"

The controller is a hardware-facing cascade. Passive wall rollers constrain
payload pitch, so the outer loop tracks tool-head position and velocity with a
smooth two-motor force allocator at a fixed cable-tension setpoint. The load-cell
inner loop converts that setpoint into reel line velocity, while the reel
encoder closes the motor velocity loop.

Turn Preview
------------
The reference generator samples a 1.2 s / minimum 0.18 m future path horizon.
Heading change over that interval estimates curvature. The reference speed is
limited by the configured 0.06 m/s^2 lateral-acceleration budget, and the change
between current and preview velocity supplies acceleration feedforward. This
lets the force controller brake and redirect before reaching a corner.

Estimated feedback:
  yhat = [p_x, p_z, v_x, v_z, phi, omega, l, ldot, T]^T

Command:
  u = [F_L_cmd, F_R_cmd, ldot_cmd]^T

Cable tension is not an ideal force command. The allocator produces a bounded
setpoint T_ref, and the physical reel/cable/load-cell loop realizes it.

The experimental direct NMPC remains available for comparison. A nonlinear
iterate that reaches the iteration limit is not declared successful; the
sensor cascade is used instead.

Cable Model
-----------
The active branch uses a compliant unilateral steel cable:
  d = ||anchor - cable_mount(p, phi)||
  delta = d - l
  T_spring = max(0, k delta + c delta_dot)
  tau_T Tdot = T_spring - T
  T >= 0

The cable can pull when taut and cannot push. Reel speed and motor thrust have
their own first-order states, so the NMPC predicts actuator lag rather than
assuming instantaneous commands.

Tilt Policy
-----------
Pitch and pitch rate come from the payload IMU. A damped pitch command is part
of the requested wrench, while bounded allocation trades pitch correction
against force tracking when the underactuated geometry reaches a limit.

Control Priority
----------------
  1. Track x-z position/velocity within the acceleration limit.
  2. Constrain pitch mechanically with passive wall rollers.
  3. Regulate cable tension to 0.45 N without slack.
  4. Respect 92% thrust reserve and the 0.10 m/s operational reel limit.
  5. Prevent load-cell integral windup while a bound is active.

CoppeliaSim Sensor Feedback
---------------------------
The 3D runner defaults to:
  --feedback-mode sensor

That mode does not feed exact CoppeliaSim position or velocity to the controller.
It simulates the intended hardware measurements:
  reel motor encoder -> paid-out cable length and reel speed,
  cable-angle encoder -> cable angle at the top guide,
  load cell -> cable tension,
  payload IMU -> raw angular rate and specific force.

The estimator reconstructs the cable-mount position from cable length and
angle, corrects elastic stretch using load-cell tension and cable stiffness,
removes the attitude-dependent cable-mount offset, estimates attitude from raw
gyro/accelerometer measurements including gyro bias, and fuses differentiated
geometry with gravity-compensated IMU acceleration for payload velocity.

External Plant and Safety
-------------------------
The CoppeliaSim path asks the controller only for commands. The controller does
not integrate its internal 2D plant and the 3D plant no longer applies reel lag
for a second time. If a nonlinear solve is infeasible or numerically unusable,
the same bounded sensor cascade supplies thrust allocation and load-cell reel
control instead of holding a stale command indefinitely.

The wall-normal preload and roll/yaw restraint are explicit passive mechanical
guide assumptions. They are not presented as feedback from sensors that do not
exist in the proposed hardware list.

Use --feedback-mode ground-truth only as an estimator comparison baseline.
